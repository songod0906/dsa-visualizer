# Design System

## Product Identity
This app is not a generic SaaS dashboard. It is a learning instrument for algorithm thinking.

## Desired Feel
- Visual, tactile, precise.
- Closer to Scratch plus VisuAlgo than Notion plus dashboard.
- Every interaction should teach algorithm state.

## Anti-Slop Rules
- No generic purple-gradient SaaS look.
- No decorative cards without learning function.
- No fake glassmorphism unless it improves hierarchy.
- No walls of explanatory text.
- No generic AI tutor copy.
- No component may be added without a clear learning purpose.

## UI Hierarchy
Primary focus:
1. Current algorithm state.
2. User action or next step.
3. Code and block relationship.
4. Explanation.

Secondary:
- badges
- metadata
- progress labels
- helper copy

## Interaction Requirements
Every learning UI must answer:
- What changed?
- Why did it change?
- What should the learner do next?
- What state is the algorithm in now?

## Current Scope Guardrail
Design improvements should make Linear Search excellent first, then Level 4 block-built Linear Search, then Binary Search. Do not add broad new learning surfaces before the arrays/search loop is strong.
